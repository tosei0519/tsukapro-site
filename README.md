# つかプロ 公式サイト

画面で学ぶ前に、手でワクワクを。「つかプロ（掴めるプログラミング）」の公式サイトと、チーム用の管理者画面です。
HTML・CSS・JavaScriptだけで作った静的サイトなので、ビルドは不要です。

```
index.html          公式サイト（一般公開）
css/ js/            公式サイトの見た目と動き
assets/             ロゴ（logo.png / logo-mark.png / favicon.png）
admin/              管理者画面（経費・今やること・予定・メンバー・メモ）
slides/             発表スライド（/slides/ で開く。ページ送りはブロックとロボットの演出）
```

## 文字のアニメーション（js/textfx.js）

HTMLの要素に `data-fx="..."` を付けると使えます（素のJavaScript。ライブラリは不要）。
`blur`（ぼかしから現れる）、`split`（1文字ずつ起き上がる）、`scramble`（文字が入れ替わって落ち着く）、`rotate`（言葉が入れ替わり続ける）、`vprox`（カーソルが近づくと太くなる）、`focus`（枠がことばを追う）、`velocity`（スクロールの速さで流れる）、`curve`（曲線の上を流れる）。`shiny` と `agrad` のクラスは、光が走る文字とグラデーションが流れる文字。
動きは、初期状態で「ふつう」（動きあり）です。フッターの「動き」ボタンで「少なめ」（ふわっと出るだけ）に切り替えられます。

## ブロック読み取り（reader/）

カメラでブロックを読み取り、上から順の命令にして、Bluetoothでロボットに送る試作です。`/reader/` を開きます。
`/reader/#sample` で、サンプル画像（Tinkercadの設計画面）を使って試せます。

- 読み取りのしくみ：オレンジ色を抜き出す → ブロックのつなぎ目（細い所）で分ける → 形を「覚えた4つ」と比べる
- 使う前に：実物のブロックを上から 後ろ・右・前・左 の順につなげて置き、「この4つを覚える」を押す
- 色が合わないとき：「色と向きの調整」のつまみで、オレンジが青く光るように合わせる
- 少し傾いても読めます（±10度まで自動で補正）
- ロボットへ送る文字：前=F、後ろ=B、右=R、左=L を並べて最後に改行（例 `BRFL\n`）。BluetoothはNordic UART（NUS）の書き込み用UUIDが初期値です
- Bluetoothは、Chromebook・Windows・AndroidのChrome/Edgeで使えます（iPadのSafariは不可）
- 前・後ろ・右・左の動きの意味（右＝その場で90度、など）は、見本の動きを仮に決めたものです

## スライド（slides/）

`slides/index.html` の `<section class="slide">` が1枚ずつのスライドです。文章を直接書き換えてください。
`class="todo"` の場所は未記入の目印です（Hキーで隠せます）。

| キー | 動き |
| --- | --- |
| → / Space / Enter | 次へ（ブロックが組み上がり、ロボットが走ってめくる） |
| ← / Backspace | 前へ（ロボットが逆向きに走る） |
| T | 演出のON/OFF（OFFならフェードだけ） |
| Q | 演出の速さ（ふつう/はやい） |
| F | 全画面 |
| N | 発表者メモ |
| H | 未記入の目印を隠す |

## 手元で見る

```bash
python3 -m http.server 8123
```

ブラウザで http://localhost:8123 を開きます。

## GitHub Pages で公開する

1. GitHubで新しいリポジトリを作り、このフォルダの中身を push する
2. リポジトリの **Settings → Pages → Build and deployment** で、Source を `Deploy from a branch`、Branch を `main` / `(root)` にする
3. 数分後に `https://<ユーザー名>.github.io/<リポジトリ名>/` で見られる

## 管理者画面について

`/admin/` を開くと、ログイン画面が出ます。**初期状態は、デモ用の仮ログインです。**

- 仮のパスコード: `tsukapro2026`（`admin/admin.js` の `PASS_HASH` を変えると変更できます）
- パスコードの確認はブラウザの中で行うため、**本当の意味でのアクセス制限にはなりません**（GitHub Pagesの公開サイトは、誰でもファイルの中身を読めます）
- データは、**そのブラウザの中にだけ**保存されます。他の端末やメンバーとは共有されません
- 公開リポジトリには、個人情報や実際の経費データを入れないでください

### チームで共有する管理画面（Claude）

Firebaseを使わずに共有する方法として、管理画面を claude.ai の共有ページとして用意してあります（今やること・予定・メンバー・メモ。経費は別ページにリンク）。
ログインは claude.ai のアカウントで行い、ページの「共有」メニューで、メンバーを「編集者」か「共同作業者」として招待した人だけが入力できます。データは claude.ai 側に保存されます。
`/admin/` のログイン画面から、リンクで開けます。

### 管理者画面を本物にする（Firebase・どちらか好きな方）

メールアドレスとパスワードでログインし、メンバー全員で同じデータを見られるようにします。無料の範囲で足ります。コードは用意してあるので、Firebase側の設定と、設定値の貼り付けだけです。

1. [Firebaseコンソール](https://console.firebase.google.com/) で、新しいプロジェクトを作る（Googleアナリティクスはオフでよい）
2. 左の「構築」→ **Authentication** →「始める」→ ログイン方法で **メール / パスワード** を有効にする
3. Authentication の「ユーザー」タブで、メンバーのメールアドレスとパスワードを1人ずつ追加する（公開の登録画面は無いので、ここで追加した人だけがログインできます）
4. 「構築」→ **Firestore Database** →「データベースを作成」（本番モード、場所は `asia-northeast1`（東京））
5. Firestore の「ルール」タブに、このリポジトリの `firestore.rules` の中身を貼り付ける。**`member1@example.com` などの部分を、メンバーの本当のメールアドレスに書き換えて**「公開」する（このルールが、データを守る本体です）
6. プロジェクトの設定（歯車）→「マイアプリ」→ ウェブアプリ（`</>`）を追加し、表示された設定値を、`admin/firebase-config.js` の `window.TSUKA_FIREBASE = null;` を置き換える形で貼り付ける
7. Authentication の「設定」→「承認済みドメイン」に、公開するドメイン（`<ユーザー名>.github.io`）が入っているか確認する
8. `git push` して、`/admin/` を開く。メールアドレス欄が出れば、本物のログインに切り替わっています

メモ：
- 設定値（apiKeyなど）は、公開されても問題ない種類の値です。守っているのは、5のルールです
- データは、画面ごとに1まとまりで保存します。2人が同時に同じ画面を編集すると、あとから保存した人の内容になります（入力中は、他の人の変更で画面が動かないようにしています）
- 今のデモのデータは、クラウドには移りません。必要なら、各画面の「表をコピー」で控えを取ってください
